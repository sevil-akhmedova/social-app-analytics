# Проверка сохранённой выгрузки

После учебного задания была сохранена итоговая таблица `sevil_table` за период с 22 июля по 14 августа 2026 года: 1 608 строк, 23 дня с данными.

При разборе выгрузки проверены сочетания `event_date`, `dimension`, `dimension_value`. Повторяющихся ключей не найдено. Для такой же базовой проверки своего CSV можно использовать [скрипт на pandas](../scripts/check_export.py).

Также при просмотре выгрузки отмечено, что 28 июля отсутствует среди дат, а 22 июля суммы `messages_sent` и `messages_received` различаются на 57 сообщений. Поздняя выгрузка не доказывает, что те же особенности присутствовали при сдаче задания 27 июля: данные учебного симулятора могли меняться.

Куратор отдельно отметил сильное занижение `users_received`. В первоначальном SQL-запросе использовались одновременно `receiver_id AS user_id` и `uniq(user_id)`. В версии для портфолио отправитель назван `sender_id`, чтобы избежать неоднозначности. Изменение не проверялось повторным запуском на исходной базе.

Здесь проверяется структура сохранённого результата. Точность расчётов по исходным событиям такой проверкой подтвердить нельзя.
