# ETL продуктовых метрик на Airflow

*Ежедневная обработка событий ленты новостей и мессенджера с формированием срезов для аналитической отчётности.*

## Задача

Автоматизировать расчёт продуктовых метрик за предыдущий день и сохранять результаты в ClickHouse. Итоговая таблица позволяет сравнивать активность пользователей по полу, возрасту и операционной системе без повторного расчёта показателей из сырых событий.

## Как устроен процесс

```mermaid
flowchart TD
    F[feed_actions: просмотры и лайки] --> M[Объединение метрик по user_id]
    S[message_actions: отправки и получения] --> M
    M --> U[Добавление пола, возраста и ОС]
    U --> G[Срез по gender]
    U --> A[Срез по age]
    U --> O[Срез по os]
    G --> C[Объединение срезов]
    A --> C
    O --> C
    C --> L[Загрузка в ClickHouse]
```

Процесс реализован в DAG `sevil_ahmedova_etl` с ежедневным запуском в Apache Airflow. Отдельные задачи рассчитывают метрики ленты и сообщений, объединяют данные по пользователям и формируют три среза.

| Метрика | Что показывает |
|---|---|
| `views` | Количество просмотров в ленте |
| `likes` | Количество лайков |
| `messages_sent` | Количество отправленных сообщений |
| `messages_received` | Количество полученных сообщений |
| `users_sent` | Сумма числа уникальных получателей сообщений каждого пользователя |
| `users_received` | Сумма числа уникальных отправителей сообщений каждому пользователю |

В двух последних метриках уникальные собеседники сначала считаются для каждого пользователя, а затем суммируются внутри среза. Поэтому это не число уникальных пользователей всего сегмента.

**Инструменты:** Python, pandas, SQL, ClickHouse, pandahouse, Apache Airflow.

[Посмотреть код DAG](dags/user_metrics_etl.py)

## Результат

В учебной среде DAG создавал и заполнял таблицу `test.sevil_table`. Для каждой даты в ней сохраняются название среза (`gender`, `age`, `os`), его значение и шесть рассчитанных метрик.

В сохранённой выгрузке содержатся **1 608 строк за 23 дня** (22 июля - 14 августа 2026 года). Проверка сочетаний `event_date`, `dimension` и `dimension_value` не обнаружила повторяющихся строк. [Подробнее о проверке](docs/validation-notes.md).

## Запуск и ограничения

Для запуска нужны Apache Airflow 2.x, библиотеки `pandas` и `pandahouse`, а также доступ к исходным таблицам ClickHouse. Подключения задаются через переменные окружения, перечень указан в [.env.example](.env.example). Этот файл служит образцом и сам по себе не настраивает окружение Airflow.

Проект создан в рамках обучения в Karpov.Courses. Исходные учебные события не публикуются. Первоначальный DAG выполнялся в учебной среде; после подготовки к публикации обновлённый код не запускался повторно на исходных таблицах. При работе с большими объёмами данных передачу DataFrame между задачами и повторную загрузку за одну дату потребовалось бы доработать.
